## 1. อาการที่ผู้ใช้เจอ

หน้า **ผู้ปกครอง → ตั้งค่า → ภารกิจ** หัวการ์ดขึ้น `งานบ้าน (12)` แต่จอแสดงจริงแค่ **9 รายการ**
เลื่อนหน้าจอลงต่อไม่ได้เลย ของที่เหลือเข้าไม่ถึง (เปิดจากเบราว์เซอร์บนเดสก์ท็อป)

## 2. สาเหตุที่แท้จริง

**ไม่ใช่ปัญหาข้อมูล** — `parent.chores.list` (`apps-script/Crud.gs:102`) คืนทุกแถวจากชีต ไม่มี filter/limit
และ `readAll_` (`apps-script/Db.gs:20`) อ่านทั้งตาราง เลข 12 จึงถูกต้อง

**เป็นปัญหาโครงหน้าจอ** — CSS เดิมเป็นแบบนี้:

```css
html, body, #root { height: 100%; }        /* ล็อกสูงเท่าจอ */
.app      { min-height: 100dvh; display: flex; flex-direction: column; }
.app-body { flex: 1; padding-bottom: 100px; }
```

วัดค่าจริงในเบราว์เซอร์: `body = 665px` แต่ `.app = 1158px` — เนื้อหาทะลุออกนอก body ไปเกือบครึ่ง
แล้วไปพึ่งว่าเบราว์เซอร์จะยอมเลื่อนหน้าเว็บให้ ซึ่งใช้ไม่ได้เมื่อหน้าเว็บถูก serve อยู่ใน
**sandbox iframe ของ Apps Script** (`iframe#sandboxFrame` ที่ Google ตั้ง `height:100%` ให้)
ผลคือทุกอย่างที่เกินขอบจอกลายเป็นของที่เข้าไม่ถึง

ปัญหาซ้อนอีกชั้น: `.app-body` เผื่อที่ล่างไว้ตายตัว `100px` แต่แผง HUD ล่างสูงจริง **85px**
บวกปุ่มที่เลือกยกขึ้นอีก **17px** บวก `env(safe-area-inset-bottom)` ของเครื่องจอบาก — เกิน 100px

## 3. สิ่งที่แก้

### 3.1 ให้ส่วนเนื้อหามีสกอลบาร์ของตัวเอง (`frontend/src/styles.css`)

```css
html, body, #root { min-height: 100%; }    /* ไม่ล็อก — ให้ยืดตามเนื้อหา */
.app      { height: 100dvh; display: flex; flex-direction: column; }
.app-body { flex: 1; min-height: 0; overflow-y: auto;
            padding-bottom: calc(112px + env(safe-area-inset-bottom)); }
```

`min-height: 0` **จำเป็น** — ถ้าไม่ใส่ flex item จะไม่ยอมหดให้เล็กกว่าเนื้อหา สกอลบาร์จะไม่เกิด

ได้ประโยชน์ทุกหน้าเพราะใช้โครงเดียวกันหมด (`ChildApp.jsx:20`, `Login.jsx:8`, `ParentApp.jsx:21`)
— แท็บตรวจงาน แลกของ ของรางวัล และหน้าเลือกตัวละครของลูก หายปัญหาเดียวกันไปด้วย

### 3.2 Sessions ไม่โตไม่หยุดอีกต่อไป (`apps-script/Auth.gs`)

เดิม `getSession_()` ถูกเรียก **ทุก request** และอ่านทั้งตาราง Sessions ทุกครั้ง
แต่แถวจะถูกลบก็ต่อเมื่อกดออกจากระบบ ส่วน session อายุ 30 วันเป็นค่าเริ่มต้น
เด็กแทบไม่กดออก → ล็อกอินทุกครั้งคือเพิ่มแถวถาวร → ทุกคลิกช้าลงเรื่อยๆ แบบสะสม

- แคช `token -> session` ไว้ 5 นาทีใน `CacheService`
- เพิ่ม `pruneSessions_()` ล้างแถวหมดอายุ เรียกตอนล็อกอิน (ล็อกอินไม่บ่อย เก็บกวาดตรงนั้นถูกที่สุด)
- `logout_()` ล้างแคชทันที สิทธิ์จึงไม่ค้าง
- ข้อจำกัดที่ยอมรับ: ถ้าปิดใช้งานเด็กระหว่างนั้น session เดิมยังใช้ได้อีกไม่เกิน 5 นาที

### 3.3 batch endpoint — ลดจำนวนรอบ (`apps-script/Code.gs`, `frontend/src/api.js`)

การเรียก Apps Script แต่ละครั้งคือการรันสคริปต์ใหม่ทั้งรอบ ซึ่งช้ากว่า API ปกติมาก

- action ใหม่ `batch` รับได้สูงสุด 10 รายการต่อรอบ แต่ละรายการล้มเหลวแยกกันได้
- กัน batch ซ้อน batch และกัน calls ว่าง
- ฝั่ง frontend เพิ่ม `callBatch()`
- ใช้แล้วที่: หน้าแรกของเด็ก 2→1 รอบ, ร้านค้า 3→1 รอบ, แท็บภารกิจของผู้ปกครอง 2→1 รอบ

### 3.4 ไม่มีสปินเนอร์หมุนค้างตลอดกาล (`frontend/src/components.jsx`, `api.js`)

เดิมทุกหน้าทำแบบเดียวกัน: โหลดพลาด → ขึ้น toast → ปล่อย state เป็น `null` → สปินเนอร์หมุนไปเรื่อยๆ
โดยผู้ใช้ไม่รู้ว่าต้องทำอะไร

- `call()` ใส่ timeout 25 วินาที (`AbortController`) พร้อมข้อความภาษาไทยแยกกรณีหมดเวลา/ต่อไม่ติด
- hook ใหม่ `useLoad()` + `<ErrorRetry>` — โหลดพลาดขึ้น ⚠️ พร้อมปุ่ม "ลองใหม่"
- เปลี่ยนมาใช้ครบทั้ง **12 จุด** ที่โหลดข้อมูลในทั้ง 3 หน้าจอ

### 3.5 สลับแท็บแล้วดีดขึ้นบนสุด (`frontend/src/components.jsx`)

ผลพวงจากข้อ 3.1 — พอ `.app-body` เป็นตัวเลื่อนเอง การสลับแท็บจะค้างอยู่ตำแหน่งที่เลื่อนไว้ของแท็บก่อนหน้า
เพิ่ม `<AppBody scrollKey>` และ `scrollBodyTop()` ครอบทั้งแท็บหลักและแท็บย่อยในหน้าตั้งค่า

## 4. วิธีที่ใช้ตรวจสอบ

ไม่มี test suite ในโปรเจกต์ จึงตรวจด้วยการรันของจริง:

- **จำลอง production ให้ตรง** — ดึง HTML/CSS ตัวห่อจาก URL live จริงมาดู พบว่า Google ใช้
  `iframe#sandboxFrame` ใน `<table class="full_size">` และ CSS ตั้ง `height:100%` ให้ทั้งชุด
  แล้วสร้างหน้า host เลียนแบบ วัดค่าด้วย headless Chrome (`--dump-dom`)
- **รันแอปที่ build แล้วจริงๆ** โดย stub `window.fetch` ป้อนข้อมูลปลอม (งานบ้าน 12 รายการ)
  แล้วสั่งกดเข้าแท็บ ตั้งค่า → ภารกิจ
- ผลหลังแก้: แสดงครบ 12 แถว, `.app-body` เลื่อนได้ 493px, รายการสุดท้ายพ้นแผง HUD 59px,
  สลับแท็บและแท็บย่อย scroll กลับเป็น 0, ฝั่งเด็ก (หน้าแรก/ร้านค้า/ภารกิจ) render ผ่าน batch ปกติ
- **จำลองเน็ตล่ม**: ไม่มีสปินเนอร์ค้าง ขึ้นปุ่มลองใหม่ กดแล้วโหลดครบ 12 รายการ
- **ยิง POST เข้า production จริง** หลัง deploy: batch คืนผลรายตัวถูกต้อง, กัน batch ซ้อน batch,
  กัน calls ว่าง, action เดี่ยวแบบเดิมยังทำงานปกติ

หมายเหตุ: อาการ "เลื่อนไม่ได้เลย" **จำลองใน headless Chrome ไม่สำเร็จ** (ที่นั่นเลื่อนได้ปกติ
ทั้งก่อนและหลังแก้) — ที่ยืนยันได้คือตัวเลข `body 665px` vs `.app 1158px` ซึ่งเป็นโครงที่เปราะจริง
และผู้ใช้ยืนยันภายหลังว่าเห็น 9 จาก 12 ตรงกับที่คาด

## 5. สถานะ deploy / git

| version | เนื้อหา |
|---|---|
| 21 | `min-height` แทน `height` + padding ล่างเผื่อ safe area |
| 22 | `.app-body` มีสกอลบาร์ของตัวเอง |
| 23 | session cache/prune, batch endpoint, useLoad + timeout, scroll reset |

- deployment เดิม `AKfycbyAoj…` — URL ที่ผู้ใช้เปิดอยู่ไม่เปลี่ยน
- branch `fix/scroll-and-perf` (2 commits) **ยังไม่ merge เข้า main**
  → `git checkout main && git merge fix/scroll-and-perf`
- ⚠️ **ยังไม่ได้ push ขึ้น GitHub โดยตั้งใจ** — secret `CLASP_DEPLOYMENT_ID` ใน GitHub ยังชี้
  deployment เก่า ถ้า push แล้ว CI รัน มันจะ deploy ทับขึ้น URL เก่าที่เลิกใช้แล้ว ต้องแก้ secret ก่อน

## 6. ที่ยังไม่ได้ทำ

- ยังไม่มี test suite — ทุกอย่างตรวจด้วยมือผ่าน headless Chrome
- `readAll_` ยังอ่านทั้งตารางทุกครั้งสำหรับตารางอื่น (Submissions, Points ฯลฯ)
  ตอนนี้ยังไม่เป็นปัญหา แต่จะโตแบบเดียวกับ Sessions
- ถ้าแถบเตือนของ Google โผล่ด้านบน (สูงได้ถึง 20vh) iframe จะถูกดันลง
  แผงเมนูล่างอาจตกขอบจอ — ยังไม่เจอของจริง แต่เป็นความเสี่ยงที่เหลืออยู่
